# ADR-0009: Protobuf as the Single Source of Truth for Wire Types

## Context

Two codebases — Kotlin on the phone, Rust on the desktop — plus a TypeScript UI must agree on
every wire type in TLP v1. Hand-written DTOs duplicated across three languages drift silently
and turn protocol bugs into runtime surprises. TLP is binary-framed (ADR-0003) and must evolve
forward-compatibly across app versions that will not update in lockstep. Options considered:
JSON with a shared schema (no binary framing, weak evolution rules), hand-written types guarded
by conformance tests (drift moved, not removed), or generated code from one schema.

## Decision

- The five files under `/proto/tandem/v1/` — `common.proto`, `call.proto`, `calllog.proto`,
  `pairing.proto`, `transport.proto` — are the **only** schema source. Kotlin bindings are
  generated by protobuf-gradle-plugin in the app module; Rust bindings by prost-build in
  `tandem_proto`'s `build.rs`, which compiles the repo-root proto directory directly — no
  vendored copies, no hand-duplicated DTOs anywhere.
- **Generated types are confined to codec edges.** On Android, `EnvelopeCodec.kt` is the only
  file importing generated proto classes; domain and UI layers see domain models. On the
  desktop, proto-to-domain conversion happens only at the transport boundary; `tandem_core`
  never sees prost types in its public API. The TypeScript UI never sees proto types at all —
  the IPC surface is defined in `tandem_ipc::api` and exported via ts-rs (ADR-0004).
- **Version negotiation** is part of this decision's contract: proto3 unknown fields are
  preserved and ignored, so adding `Envelope` payload variants is a minor change; changing the
  semantics of existing fields is a major change. `SessionHello.protocol_min/max` negotiate;
  the phone picks the highest mutual version or rejects with
  `ERROR_CODE_VERSION_UNSUPPORTED` (rules in docs/06-transport-and-protocol.md).

## Status

Accepted.

## Consequences

- A schema change is one edit plus regeneration on both sides; incompatibilities surface at
  compile time in two languages instead of at runtime on one.
- Codec-edge confinement keeps domain layers framework-free and unit-testable, at the accepted
  cost of an explicit mapping layer (`EnvelopeCodec.kt`; `tandem_core::model` conversions).
  This is deliberate: the mapping layer is where wire compatibility is reasoned about.
- Any change under `/proto` is a protocol decision, reviewable as such — the diff of a `.proto`
  file is the diff of the protocol.
- Codegen adds build-time tooling on both platforms, wired through the build plugins and the
  `tools/gen-proto` scripts; setup is documented in docs/13-build-and-setup.md.
- The proto text itself is embedded verbatim only in docs/06-transport-and-protocol.md; all
  other documents reference message names against that single copy.
